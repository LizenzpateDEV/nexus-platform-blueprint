# Contributing

## Arbeitsregel

Jede Änderung muss nachvollziehbar sein.

## Ablauf

1. Neue Idee als Issue anlegen
2. Spezifikation im passenden Blueprint-Dokument ergänzen
3. Review durchführen
4. Erst danach technische Umsetzung starten

## Commit-Regeln

Beispiele:

- docs: add CRM blueprint
- arch: add tenant architecture decision
- security: define RBAC rules
- ai: add AI governance principles

## Keine Schnellschüsse

Keine Architekturentscheidung wird direkt im Code getroffen. Wichtige Entscheidungen gehören in den ADR-Ordner.
